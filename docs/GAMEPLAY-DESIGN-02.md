# 勇敢人生：系统设计方案（第二步）

日期：2026-11-03。状态：方案草案，承接 GAMEPLAY-DESIGN-01.md；尚未进入数值平衡、UI 原型及实现。使用 game-system-design，自研项目。

## 1. 设计目标与范围

核心承诺：过自己的日子，尝试一件在意的事，与别人留下共同经历。

首段为成年独立生活中的一周：保留吃饭、工作、出行、睡眠与实时慢节奏，加入一次可自主安排的短篇。首段采用美绪的演出与春香的视觉设计协作；职业压力来自现有工作收入，不要求玩家必须就业，也不要求同时攻略任何人。

本轮规则只适用于首个样段，暂不重做全部职业和恋爱。6–17 岁玩家继续现有内容；成年后自然触发样段。更早试玩可直接选择 18 岁开局，不改年龄速度。

### 系统结构

生活状态与人物关系 → 可遇见的机会 → 自主接下/婉拒 → 准备与约定 → 关键选择 → 结算与人物回应 → 回忆入册/家中陈列 → 后续机会。

四个新增职责：机会记录当前进展；经历记录发生过什么；奖励记录哪些已发放；回忆记录值得展示的结果。四者引用同一个事件实例，避免各存一套互相矛盾的进度。

## 2. 日常机会：有方向，但不成为打卡表

### 2.1 今日呈现

主页默认最多突出三条：一条紧急生活需求、一条玩家正在推进的事、一条来自人物或城市的机会。某类没有合适内容就不凑满。全部进行中内容在手机查看。

生活提醒来自实际需求，如精力过低或房租临近；不会因为玩家未完成提醒再次扣分。低优先级机会不遮挡故事，也不连续弹窗。机会没有连续签到奖励，不按现实日期过期。

机会卡需显示：谁发来、为什么与玩家有关、何时可处理、行动所需时间/费用、是否可推迟、失约有什么结果。未知的故事结果可以保留悬念，确定的成本不能隐藏。

### 2.2 生命周期

| 状态 | 玩家可做什么 | 转移条件 |
|---|---|---|
| 已收到 | 查看、接下、婉拒、稍后处理 | 接下进入准备；婉拒归档；忽略仍在手机 |
| 准备中 | 完成可选准备、查看进展、提出延期或退出 | 确认赴约进入已预约 |
| 已预约 | 准备、前往、提前改约、说明退出 | 约定窗口到来可入场；窗口结束未出现则待回应 |
| 待回应 | 解释、道歉、结束这段事 | 玩家选择修复或归档，不强制打开剧情 |
| 进行中 | 在关键节点做选择 | 完成后进入待结算 |
| 已归档 | 查看结果、回忆和相关人物 | 本实例不再次发奖；新机会使用新实例 |

首段邀请在收到后的若干游戏日内可确认；准确期限在数值阶段定。过期只代表本次邀请结束，不永久关闭 NPC 或职业。手机保留说明，下一次相遇可自然提起。

首段只允许一个主要短篇处于准备/预约/进行阶段，另一个短篇仍可被看见并稍后接下。生活活动及普通社交不受此限制，以控制内容竞争和测试复杂度。

### 2.3 预约、时钟与跳日

- 约定使用游戏日和时间窗口，完全不读取现实星期或离线时间。
- 接下邀请时先选一个可行演出窗口；系统检查现有约定，提前展示冲突，不能替玩家承诺。
- 首段提供一次提前改约，只延后到预设下一场，不无限拖延；改约不额外获得勇气。
- 到窗口时给非阻断提醒；只有玩家打开关键对话时才沿用 ui.reading 暂停。不能靠弹窗把全世界无限冻结。
- 连续工作、睡眠或长途出行会跨过已预约窗口时，执行前提示冲突，并明确继续就视为未赴约；选择取消本次动作不扣资源。
- 主动退出并通知 NPC 与无通知失约是不同分支；两者均可继续游戏。
- 跳日不能静默吞掉已预约事件：当天存在关键预约时，沿用 skipReason 的禁止跳日提示；允许玩家先改约或明确取消。未接邀请不锁跳日。
- 退出或切后台保持本地进度；本项目不新增离线推进，所以重新打开不会因真实离线而失约。

## 3. 勇气：奖励一次有意义的行动

### 3.1 奖励来源

| 来源 | 条件 | 限制 |
|---|---|---|
| 首次尝试 | 第一次确实执行某类重要行动，如登台 | 每代、每类一次；只点“接下”不算 |
| 表达与边界 | 在具体情境中明确求助、拒绝或退出并承担后果 | 每个故事节点一次；取消/接下反复切换不算 |
| 面对后果 | 失误或失约后完成一次修复行动 | 对应真实的未解决事件，一次；不能重复制造同一事件 |
| 既有课题 | 满足课题独立目标 | 不与同一经历重复叠加发放同类奖励 |

成功或失败不直接决定“是否勇敢”。结果仍影响收入、心情、关系和后续台词；勇气看行动与上下文。平静休息无需每次证明勇敢，只有相关故事中表达边界才发经历奖励。

### 3.2 去重与旧规则调整

奖励以“代际 ID + 故事/行动类别 + 节点”生成唯一键，先检查是否已经领取。重复点击、读档恢复后的页面回调和动画结束回调只能提交一次。

现有 story 标签会固定发勇气，需要将其改为表达风格标记：选择“勇敢/发疯”文字本身不自动获得固定收益，奖励由节点规则发出。避免同一次行动同时拿 first、标签、课题三份重复勇气；最终仲裁顺序与奖励量进入第三步统一配置。

告白取消重复失败递增奖励。失败后同一关系进入明确的回应阶段：NPC 表示愿意进一步了解时才开放后续推进；明确拒绝时尊重边界，不开放每日重试按钮。可改为友情后续；不以高价礼物或御守绕过明确拒绝。

勇气商店保留神秘营业规则和旧物故事。日常进展查看、回忆查看与修复入口放在手机，不要求玩家等待雨夜。御守可改善允许随机的表现波动，不能覆盖人物意愿。具体商品重配在数值阶段处理。

## 4. 关系经历：保留好感，增加少量事实

不增加第二条“信任值”或大型性格面板。保留好感及认识/朋友/恋人等状态，增加可阅读的共同经历。

| 经历 | 记录示例 | 后续用途 |
|---|---|---|
| 一起完成 | 和美绪参加第一次小演出 | 后续邀请与对话替换 |
| 兑现约定 | 按约带来了手写节目单 | NPC 相信某项具体能力 |
| 处理分歧 | 接受春香简化海报，而非要求她熬夜重画 | 后续协作方式和人物回应 |

每条记录包括人物、故事实例、游戏日期、选择、结果。玩家能看到自然语言描述，底层使用稳定 ID。

好感是熟悉程度，经历是做过什么。关键支线可以要求一个相关经历，普通聊天和见面仍然开放。不能为了关系资格让玩家必须选择恋爱；友情与恋爱共享经历但有不同措辞。

一次失约只产生与该事件相关、可说明的后果；不清空既有经历，不默认每天持续衰减惩罚。后续修复改变“这件事是否说开了”，不能删除曾经失约的事实。

NPC 仍有自己的时间表。预约活动在指定窗口提供事件专用会面入口，覆盖当时的普通位置展示，但不能让同一 NPC 同时出现在两个地点。活动结束恢复正常时间表。

## 5. 回忆：从结果到可见变化

每个首段结局只产出一件主要纪念物，外观和文字随结果变化。纪念物不提供永久最优属性，不允许出售后重复刷取；获得后自动进入手机回忆册，即使家里没位置也不丢失。

首段做一个固定“回忆角”展示位，复用已有房间旁的界面空间，不立刻改造整套墙面/家具格子系统。玩家选择一件展示，点击可打开故事摘要、人物和当时选择；其他仍在回忆册。后续才考虑墙面摆放与相册家具。

已有旧物商品继续作为家具；新回忆物使用独立目录，避免其 ID 被 FURNITURE 查找导致错误。即使收起纪念物，共同经历仍然有效。

## 6. 可玩样段：第一次登台

### 6.1 触发与人物

成年玩家认识美绪后，在非其他关键剧情进行时收到邀约。成年开局不要求很高好感，也不强迫选择艺人职业。美绪想试一段与朋友合演的小节目；春香可协助节目单。认识春香是可选准备，未认识也有自行制作路径。

### 6.2 准备选择

| 行动 | 确定代价 | 改变什么 | 替代路径 |
|---|---|---|---|
| 独自练习 | 时间与精力 | 熟悉流程，降低可预见失误 | 单人简短节目 |
| 和美绪排练 | 时间、到场约定 | 双方知道如何互相接应，产生共同经历 | 无需高能力即可协作 |
| 请春香做节目单 | 沟通时间和对方可用窗口 | 宣传样式与协作分支 | 手写节目单，不扣关系 |
| 借用或租用设备 | 前者要沟通；后者花钱 | 演出形式与准备难度 | 场地基础设备可免费使用 |
| 多打一班工 | 工作时间与疲劳 | 资金更宽裕，准备时间变少 | 没有工作也能演出 |

首段最多识别“练习过、共同排练过、设备方案、节目单方案”四类准备事实。同类重复练习可沿用基础能力收益，但不无限提高本故事结果，不重复发故事奖励。没有必需购买项，不能因贫穷被挡在主体验外。

### 6.3 转折与规则

演出前美绪说明自己最近状态不好，原计划完整合演可能撑不住。玩家可选择：

- 缩短节目一起上台：保留陪伴，演出规模变小；会沿用排练时约定的互相接应方式。
- 自己承担更多：若练习过且精力足够，执行独立部分；不满足时按钮说明缺少条件，并提供简化版本。
- 一起取消并通知场地：损失部分已支出的租赁费用，但避免无通知爽约；保留友谊与新约定。

不允许“逼美绪坚持”作为稳定高收益解。玩家可以表达失望，人物会回应；故事不把照顾对方设计成唯一正确答案，也允许说明自己的准备付出。

### 6.4 结局与回响

| 结局 | 判定 | 当下反馈 | 下一段反馈 | 纪念物 |
|---|---|---|---|---|
| 小舞台顺利完成 | 选择可行方案并完成核心准备 | 观众回应、人物感谢 | 美绪发来录音，可提出新合作 | 小舞台合照 |
| 出错后一起完成 | 上台但准备不足，或出现已明确提示的风险 | 失误后有补救选择，不直接整场失败 | 回看并互相调侃；获得一次独特修复经历 | 有涂改的曲目单 |
| 认真说明后取消 | 演出前明确退出并通知 | 费用结清、人物各自表达感受 | 改做一次轻松见面，不立刻再发同款邀请 | 写了一半的节目单 |
| 没有赴约 | 已确认预约但无通知缺席 | 消息询问，不强制传送 | 解释、道歉或不再合作；该实例归档 | 未使用的门票 |

首段结果由已展示的准备事实、状态和选择确定，不在最后暗骰一次“整场失败”。日后若加随机，只影响可补救的局部状况，不能否定全部准备。未赴约也有回忆，但不给缺席勇气；修复奖励同节点只能一次。

### 6.5 最小内容量

首段制作邀请、确认、准备回应、转折、结果、次日回响六类节点；四个结局共用前半段，只写条件差异。两位 NPC、一个演出地点、一套场景反馈、四种纪念物变体。普通行动不全部配独立剧情，避免每次吃饭都打断游戏。

## 7. UI 与视觉要点

保持温暖水彩、纸张与手写注记。主要强调色复用现有暖色；人物情绪通过表情、台词和小动作表达，避免只弹“好感+8”。

| 界面 | 内容与主要动作 | 必备状态 |
|---|---|---|
| 游戏主界面 | 一条当前目标，展开看其他机会 | 无目标时允许自由生活，不自动塞任务 |
| 手机·正在发生 | 邀请、预约、准备、已归档；查看、改约、退出 | 首次空状态、期限已过、状态已变化 |
| 机会详情 | 人物动机、进展、准备选项、成本、窗口与后果 | 钱不够、精力不足、人物不在、时间冲突 |
| 剧情对话 | 选项表达意图；旁注确定成本 | 暂停阅读、无法重复提交、重进恢复 |
| 联系人 | 好感与关系，下方列共同经历 | 未认识、暂无经历、存在未说开的事 |
| 家·回忆角 | 纪念物、标题、短摘要；更换与重看 | 空展示位、资源加载中、图片失败仍可读文字 |

一般行动维持简洁结算，故事关键动作展示前后差异。行动执行期间按钮禁用并可读；点击不得因动画没结束再次扣费。弹窗关闭不等于已选择。素材缺失用占位图与文字回退，不阻塞结算。

这是界面责任清单，尚非 UI 原型；后续原型和 GDD 必须使用同一清单对应。

## 8. 对现有代码的落地映射

- data/story*.js 承载台词与节点定义，engine/story.js 处理节点选择，避免新增平行剧情播放器。
- 新机会进度与预约读取独立、可序列化的数据；ui 中只放临时面板和动画状态。
- 扩展 courage.js 的奖励入口，所有来源通过统一去重后发放；不直接在组件写勇气值。
- social 的普通行动保留，新增共同经历索引；与 story.flags 的迁移边界统一定义。
- 新回忆目录只记录资源 ID，实例保存事实；改文案不需要重写历史存档。
- 现有 finish/checkStory 的每日剧情上限需要区分：随机新剧情受上限约束，已接下的关键节点与结果回响不能被随机事件长期挤掉。
- 先设计版本化存档迁移，本地和云端共用；再接界面。不将函数、组件引用或动画计时器写入存档。

## 9. 边界与异常

| 情形 | 规则 |
|---|---|
| 重复点击/动画卸载 | 同一结算 ID 只提交一次；结果可恢复展示 |
| 执行前状态变化 | 重新校验成本与窗口，失败不部分扣款；返回可读原因 |
| 动作推进跨过多个节点 | 按游戏时间顺序结算，预约先产生待回应，不连续强制弹多段剧情 |
| 突发住院 | 活动记为不可抗力，通知 NPC 并提供改约；不记故意失约，避免重复补偿 |
| 精力或资金不足 | 提供简化方案或说明退出，不能要求充值或持续刷资源 |
| 读档/恢复云存档 | 从保存状态恢复，不用 Date.now 重算预约；统一迁移和去重 |
| 旧存档 | 没有新经历则为空；已经有伴侣仍可做友情版本；既有剧情不重复发奖励 |
| 同时触发多段剧情 | 正在进行的选择优先，关键预约结果其次，新机会最后 |
| 玩家不想参加 | 婉拒后当前实例结束；不降低基础关系，不反复催促 |
| 日后进入新一代 | 奖励按代际分开；前代纪念物可传承，前代约定不会变成后代义务 |

## 10. 验收与后续验证

规则验收：接受到四结局均可走通；准备事实与结果对应；所有成本在执行前可见；读档、切页、重复点击不会重复扣费或奖励；没有参加短篇也能正常生活。

体验验证：玩家能独立找到下一步；能说明一次取舍的原因；能记住人物的一次反应；能通过家中纪念物想起事件。记录重复点击劳动、被动等待和阅读打断位置，作为第三步数值与节奏调整的依据。

## 12. 开放问题/风险项

- 首段仍可能被真实历法拉长；需要测一周真实操作时间，再决定准备窗口，暂不擅改既定慢节奏。
- 明确拒绝后的恋爱边界会改变现有重复告白玩法，需以新文本和旧存档兼容一起交付。
- 回忆角先采用固定展示位，避免为首段立即扩建房间渲染体系。
- 四结局的内容成本可控，但人物条件、事件排程和存档恢复必须成套实现。
- 下一步数值框架需确定：准备耗时、窗口长度、生活支出、勇气产出/消耗、防刷与失败恢复成本；这些值尚未定稿。
